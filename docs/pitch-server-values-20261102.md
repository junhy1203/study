# 아래 방향 얼굴 등록·서버 값 표시 지연 개선

## 변경

- 아래로 고개를 숙일 때 코와 눈 사이의 2D 간격이 줄어 판정이 반대로 움직일 수 있는 계산을 고쳤다. 이마와 턱의 3D 깊이 축을 사용하고 카메라의 가로·세로 비율을 반영한다.
- 위·아래는 약 2.6°부터 6.9°까지의 작은 기울기 변화로 방향별 4장을 모은다. 촬영 간격과 각도 차이는 계속 검사한다. 아래 방향 안내도 턱을 살짝 내리도록 바꿨다.
- 학습 시간 같은 빠른 서버 값은 랭킹 등 다른 조회가 끝나기를 기다리지 않고 도착한 시점에 화면에 표시한다.
- 같은 시점의 문서·목록 조회를 최대 16개씩 묶는다. 같은 조회는 중복 요청하지 않는다. 서버는 준비된 항목부터 NDJSON으로 전송하므로 느린 항목이 빠른 항목을 막지 않는다.
- 조회 권한과 목록 크기는 항목마다 검사한다. 한 항목의 실패는 나머지 값 표시를 막지 않는다. 조회별 요청 제한도 유지한다. 계정이 바뀐 대기 조회는 취소한다.
- 서버에서 동시 요청의 Firebase 토큰 검사와 사용자 상태 조회를 공유한다. 기존 45초 상태 확인 주기는 유지하며, 얼굴 보안 요청은 매번 별도로 계정 취소 여부를 확인한다.
- 사용자의 추가 설명에 따라 페이지 번들링·로고 변환·정적 파일 압축은 변경하지 않았다. 작업용으로 확인했던 번들러 의존성도 제거했다.

## 검증

- 전체 단위 테스트: 337개 통과.
- 실제 Chromium의 3D 방향 좌표를 사용하는 자동 얼굴 등록·저장·복구 검사 통과.
- 임시 PostgreSQL과 HTTP를 사용하는 자체 서버 검사: 26개 통과.
- 실제 배포 원본의 서버 단위 검사: 45개 통과, 통합 검사: 31개 통과.
- 빠른 값 40ms·느린 랭킹 800ms를 동일하게 적용한 통제 비교에서 값의 첫 표시가 기존 806ms → 변경 후 47ms였다. 동시 요청 12개의 원격 계정 조회는 12회 → 1회로 줄었다. 실제 사용자 계정의 운영 응답 시간을 측정한 수치는 아니다.
- 단일 조회 호환성, 16개 단위 분할, 중복 조회 제거, 항목별 오류 격리, 다른 계정 데이터 차단, 값의 개별 전송, 얼굴 요청의 별도 인증을 검사했다.
