# ADMIN 표기 수정과 3D 얼굴 스캔 검토

## 결론

일반 웹캠 영상으로 얼굴의 3D 형태를 추정하고, 고개를 돌리며 등록하는 흐름은 구현할 수 있다. 현재 사이트의 다음 단계로는 **영상 기반 본인 비교에 추정 3D 형태·자세·움직임 검사를 결합하는 방식**이 적합하다. 정확도 향상은 검증해야 하며, 3D라는 이유만으로 인식 실패나 사진·영상 위조 문제가 해결되지는 않는다.

Face ID처럼 깊이와 적외선을 실제 측정하려면 지원 하드웨어와 그 센서에 접근하는 경로가 필요하다. 현재의 범용 웹사이트를 그대로 유지하면서 모든 PC·휴대폰에서 동일하게 제공할 수 있는 방식으로 보기는 어렵다.

## 현재 구현에서 확인한 사실

- `camera.js`는 `getUserMedia`로 일반 사용자 방향 영상 스트림을 받는다. 깊이 스트림은 받지 않는다.
- `camera-inference.js`는 MediaPipe Face Landmarker를 실행한다. `camera-identity.js`의 `enrollmentPose`는 그 좌표에서 고개 방향을 계산한다.
- 본인 비교는 정렬한 얼굴 영상으로 만든 FaceRes 특징 벡터를 사용한다. 등록은 방향별 4개, 총 20개 특징을 수집한다. 얼굴의 입체 모델 자체를 등록·대조하는 시스템은 아니다.
- Google은 Face Landmarker의 출력이 영상에서 **추정한 478개 3D 특징점**이라고 설명한다. 실제 깊이 센서의 거리 측정값과 구분해야 한다. [Google 공식 문서](https://developers.google.com/edge/mediapipe/solutions/vision/face_landmarker)

## 선택지

| 방식 | 현재 웹사이트 적용 | 기대할 수 있는 것 | 주요 제약 |
| --- | --- | --- | --- |
| RGB 영상의 추정 3D 얼굴 메쉬 | 가능 | 고개를 돌리는 등록, 방향별 수집 범위 확인, 형태 일관성 보조 검사 | 실제 거리·깊이를 측정하지 않음. 형태만으로 신원 판정을 대체하려면 별도 검증 필요 |
| 여러 시점의 영상으로 더 촘촘한 3D 얼굴 복원 | 기술적으로 검토 가능 | 개인별 표면·형상 모델과 스캔 화면 | 여러 프레임, 충분한 시점, 안정적인 조명 필요. 추가 모델·연산과 인식 성능 검증 부담이 있어 우선순위 낮음. 이는 현재 요구에 대한 설계 판단임 |
| TrueDepth 등 지원 센서의 깊이 데이터 | 지원 장비와 네이티브 앱/브리지 경로에서 가능 | 실측 깊이·표면 데이터를 이용한 자체 등록 | 기기 제한과 앱 개발 필요. 범용 브라우저의 표준 카메라 입력으로 보장할 수 없음 |
| WebAuthn/패스키의 기기 본인 인증 | 웹에서 별도 인증 수단으로 사용 가능 | 기기의 인증기가 승인한 로그인/재개 | 사이트에 얼굴 메쉬를 전달하지 않으며, 학습 중 누가 앉아 있는지 계속 판단하는 기능을 대체하지 않음 |

W3C의 별도 웹 깊이 스트림 확장 규격은 구현 동력 부족으로 2022년 중단됐다. 따라서 그 초안을 근거로 일반 브라우저에서 깊이 카메라를 사용할 수 있다고 가정하면 안 된다. 장비별 전용 API·앱 연동 가능성은 별도로 확인해야 한다. [W3C 상태](https://www.w3.org/TR/mediacapture-depth/)

Apple은 지원 카메라의 픽셀별 깊이 데이터를 받는 AVFoundation API를 제공한다. 이는 자체 앱의 센서 데이터 수집 경로이며, 사용자가 기기에 등록한 Face ID 얼굴 자료를 받는 API가 아니다. Apple은 앱이 Face ID 등록 얼굴 자료에 접근할 수 없다고 명시한다. [깊이 출력 API](https://developer.apple.com/documentation/avfoundation/avcapturedepthdataoutput), [Face ID 기술·개인정보 설명](https://support.apple.com/en-us/102381)

WebAuthn도 사이트에 생체 정보를 제공하지 않고 인증기 안에서 사용자 확인에 사용한다. 특정 얼굴 템플릿을 받거나 같은 얼굴이 카메라 앞에 계속 있는지 확인하는 수단으로 해석하면 안 된다. [WebAuthn 생체 인식 규정](https://www.w3.org/TR/webauthn-3/#sctn-biometric-privacy)

## 이 사이트에 적용한다면

1. 등록 중 여러 방향의 3D 특징점을 얼굴 중심·크기·회전에 맞춰 정렬한다. 표정에 많이 변하는 입·눈꺼풀보다 상대적으로 안정적인 얼굴 구조를 중심으로 개인별 형태를 수집한다.
2. 수집한 각도의 범위와 품질에 따라 스캔 진행률을 표시한다. 실제로 충분한 시점과 품질을 확보했을 때 등록을 완료한다.
3. 인증은 기존 영상 특징 비교를 기본으로 하고, 3D 형태와 시간에 따른 움직임의 일관성을 보조 근거로 사용한다. 형태만으로 곧바로 거절하는 규칙은 실제 사용자에서 검증한 뒤 적용한다.
4. 처리와 렌더링은 기존 Worker 구조를 활용한다. 이미 추정 특징점이 있으므로 추가 연산을 억제할 여지는 있으나 실제 모바일 부하는 측정해야 한다. 촘촘한 3D 복원 모델 도입은 별도 성능 평가 대상으로 둔다.
5. 새 3D 등록 형식을 추가하면 암호화 저장·버전 구분·기존 등록 호환 처리가 필요하다. 기존에 보관된 특징 벡터만으로 개인별 3D 원본을 복원한다고 가정할 수 없으므로, 새 3D 등록이 필요할 수 있다.

등록 완료율·소요 시간, 본인 거절과 타인 수락, 조명·안경·얼굴 방향·PC/모바일 부하, 사진·화면 재생 상황을 기존 방식과 비교해야 한다. 이 검토만으로 정확도 개선이나 Face ID 수준의 위조 방지를 주장하지 않는다. **현재 단계의 권고는 추정 3D를 보조로 결합하는 방식이며, 순수 3D 인증으로 즉시 교체하는 것은 권하지 않는다.**

## 이번에 반영한 변경

- 비공개 배지 이름을 `ADMIM`에서 `ADMIN`으로 수정했다.
- 서버에 저장된 이전 이름도 자동 교정한다. 이미 두 이름이 함께 저장된 경우 하나의 `ADMIN`으로 합친다. `Contributor`와 비공개 표시 조건은 유지한다.
- 기존 표기·중복 저장 자료의 교정을 포함해 전체 단위 검사 338개와 운영 서버 검사 45개가 통과했다. 모바일 화면에서 `ADMIN` 표기와 배지 색상도 확인했다. 3D 인증은 검토만 했으며 카메라 인증 방식은 이번 변경에서 교체하지 않았다.
