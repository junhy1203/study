# 공부방 초대 · 동기화 렌더링 · WASD 수정

## 원인과 변경

- 친구 초대: `getStudySocial`에 서버가 지원하지 않는 `listScope: friends`를 보내고 있었습니다. 지원하는 요청 형태로 변경하고 목록을 즉시 열어 로딩·오류·재시도·빈 목록 상태가 보이도록 했습니다. 다른 방으로 이동한 뒤 늦게 도착한 목록은 반영하지 않습니다.
- 애니메이션 초기화: 0.5초 동기화마다 SVG 전체를 지우고 아바타를 다시 만들고 있었습니다. 방 배경·가구는 배치 변경 때만 갱신하고, 아바타는 사용자 ID별 DOM을 유지합니다. 장비나 외형이 바뀔 때만 해당 SVG를 교체합니다. 위치만 CSS로 보간하며 이모지 말풍선도 같은 이벤트 동안 유지합니다.
- WASD: 키 입력이 방 바닥에 포커스가 있을 때만 처리됐고, 반복 키가 이동 타이머를 재시작할 수 있었습니다. 입장 시 방에 포커스를 주며 가상현실 창 내부의 일반 포커스에서도 물리 WASD·방향키를 처리합니다. 첫 걸음은 즉시 시작하고 반복 입력은 적정 속도로 제한합니다. 채팅·편집 가능한 입력창·게임 팝업에서는 이동하지 않습니다.
- 캐릭터 클릭: 계속 움직이는 이펙트와 별도로 일정한 클릭 영역을 유지합니다.

## 검증

`node scripts/test-study-world-browser.mjs`는 이전의 간단한 친구 목록 가상 응답 대신 실제 `socialSnapshot` 서비스 구현을 호출합니다. 실패 후 재시도와 친구 초대·수락도 실제 서버 서비스에 연결해 확인합니다.

아바타 SVG와 실제 실행 중인 CSS 애니메이션 객체가 여러 동기화 후에도 같은 객체인지, 재생 시간이 연속 증가하는지 검사합니다. 다른 사용자의 위치가 순간 이동하지 않고 중간 좌표를 거치는지, 실제 이동 중에도 애니메이션이 유지되는지도 확인합니다.

입장 직후·도구 버튼 포커스·키 반복·채팅 입력·게임 팝업의 키 입력과 320/390/768/1024px 화면, 채팅·이모지·가위바위보·방 저장·퇴장 회귀를 검증합니다. 로그는 `tmp/world4-browser.log`에 보존합니다.

## 배포 중 발견한 운영 문제

- 관리 전송 작업자의 요청 파일 삭제 경쟁을 수정했습니다. 응답을 받은 경우 작업자가 요청 파일을 정리하며, 먼저 삭제된 파일은 오류로 취급하지 않습니다. 관련 회귀 검사와 운영 원본의 90개 테스트를 통과했습니다.
- 서버 업데이트는 `payload-extract` 단계에서 디스크 부족(`0x80070070`)으로 실패했습니다. 당시 운영 버전은 `0.1.5-world-fullscreen-20261105-r1`로 유지됐고 데이터와 서비스는 보존됐습니다.
- 기존 서명 키로 검증되는 복구 패키지는 이번에 실패한 r2/r3 배포 폴더만 정리합니다. 활성 포인터와 비교하고 링크를 거부하며 데이터·백업 경로는 정리 대상에 포함하지 않습니다. 로컬 실행 검증에서 삭제 범위·활성 버전 보존·관련 없는 오류 거부를 확인했습니다(`scripts/test-release-space-recovery.ps1`).
- 실행기를 압축해 이후 배포의 전송·디스크 사용량을 줄였습니다. 최종 운영 반영 여부는 아래 검증 결과로 기록합니다.
- 실제 서버 복구 결과: 실패한 두 폴더에서 170,790,912바이트를 회수했습니다. 복구 후 기존 활성 버전과 네 프로세스·두 API의 readiness가 정상임을 확인했습니다.
- 공간이 제한된 서버에서 런타임을 중복 저장하지 않도록 새 릴리스의 `runtime/`·`node_modules/` 중 크기와 SHA-256이 같은 불변 파일만 NTFS 하드링크로 재사용합니다. 앱 소스·호스트 실행기·변경된 파일은 새로 추출합니다. 데이터와 백업은 릴리스 바깥에 유지됩니다.
- `dotnet run --project tests/release-payload/ReleasePayload.Tests.csproj --configuration Release`로 동일 파일 재사용·변경 파일 추출·기존 파일 보존·이전 파일 삭제 후 새 파일 생존·추출 전 경로 이탈 차단을 검증했습니다.
