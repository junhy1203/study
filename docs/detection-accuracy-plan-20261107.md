# 얼굴·딴짓 감지 내부 정확도 개선 계획

작성일: 2026-11-07. 기준: 현재 작업 폴더의 미커밋 변경을 포함한 코드. 실제 서비스에 배포된 코드와 동일한지는 확인하지 않았다. 이번 작업은 검토와 계획 작성이며 제품 코드는 수정하지 않았다.

## 1. 목표와 변경 금지 범위

현재 감지 방법, 초 단위 시간, 판정 기준을 모두 유지한다. 입력 프레임의 일관성, 관측 중복 제거, 좌표·대상 연결, 비동기 결과 처리, 동일 연산의 재사용으로 내부 정확도를 개선한다.

- 얼굴: MediaPipe 얼굴 랜드마크 → 기존 정렬 영상 → RGB/조명 보정 임베딩 → 추정 얼굴 형상 비교 → 기존 투표 방식 유지.
- 행동: 눈 감김, 얼굴 부재, 얼굴·시선·학습 동작 기반 무활동, COCO 휴대폰 감지와 추적 유지.
- 모델·버전, 입력 크기, 전처리 수식, 점수 가중치, 임계값, 투표 개수, 시간 창, 재시도·유예·재개 시간을 변경하지 않는다.
- 등록 과정·18개 표본·저장 형식·기존 사용자 프로필의 의미를 유지한다.
- 인증은 시작 및 자리 복귀 시 수행한다. 학습 중 주기적 본인 인증이나 새 행동 감지 규칙을 추가하지 않는다.
- 숫자가 같아도 측정 단위나 타이머 기산점이 바뀌면 동작 변경이다. 임의의 평활화·추가 지연·새 품질 컷오프를 정확도 개선 명목으로 넣지 않는다.

기본 `phonePolicy='tracked'`는 위 프레임 추적 규칙으로 멈춘다. `FOCUS_LIMITS.phone=750`을 기본 경로의 확정 시간으로 오해하면 안 된다. 750ms는 레거시 경로에서 사용한다. `identity=90000`, `headIdle=30000` 상수의 존재만 보고 주기 인증·30초 무활동이 실행된다고 해석하지 않는다. 현재 인증의 90초 통계는 주기 인증 조건이 아니다.

표 밖의 인라인 숫자도 동결 대상이다. 첫 구현 전에 관련 함수의 수치·비교 연산·분기 순서를 목록화하고 회귀 fixture로 보존한다.

## 4. 확인한 문제와 검증할 후보

### A. 손 검출 순서를 실제 움직임으로 오인 — 재현 확인

`extractFocusSignals`는 손목 뒤에 `handResult.landmarks` 배열 순서대로 손끝을 넣는다(camera-inference.js:65). `createStudyMotionTracker`는 같은 배열 인덱스끼리 비교한다(92).

정지한 손끝 A=(.2,.5), B=(.8,.5)를 `[null,null,A,B]` → 400ms 뒤 `[null,null,B,A]`로 전달하면 반환값이 false → true다. 물체의 위치는 같은데 학습 동작이 생성된다. 이것이 실제 무활동 시간을 얼마나 잘못 초기화하는지는 통합 재현이 추가로 필요하다.

### B. 휴대폰 완료 시 같은 얼굴 관측 재입력 — 코드 경로 확인, 실제 오탐 영향 검증 필요

`acceptPhoneObservation`은 `latestFaceResult`에 새 휴대폰 관측만 붙여 현재 수신 시간으로 `applyResult`를 호출한다(camera.js:222–227). 상태 머신은 얼굴 frame ID를 구분하지 않는다. 3000ms 이상 오래된 결과는 차단하지만, 그 안에서는 같은 눈 감김·시선·인증 상태가 여러 번 전달될 수 있다.

반복 이벤트가 졸음·복귀·인증 통계에 주는 영향을 재현해야 한다. 단순히 모든 타이머를 촬영 시간으로 바꾸는 것은 현행 시간 의미를 바꾸므로 금지한다.

### C. 캐시의 세션·좌표계 소속 불명확 — 코드 경로 확인

epoch 전환은 휴대폰 캐시를 초기화하지만(camera-inference.js:170), pose/hand, studyMotion, 확대 얼굴 검색의 lastBounds/lastFaceTime 등은 detector 수명 동안 남는다. 몸·손은 400ms 간격으로 갱신된다. 다른 epoch 또는 영상 크기 변경 직후 오래된 좌표가 검색 영역·학습 움직임·손바닥 보정에 사용되는지 확인해야 한다.

### D. 휴대폰 지연 계산의 시간 기준 — 정확한 차이 확인

`completedAt = time + performance.now() - startedAt`(camera-inference.js:219)는 메인 측 촬영 시각에 worker 내 실행 시간을 더한다. createImageBitmap 및 worker 큐 대기 시간은 이 완료 시각에 반영되지 않는다. UI에서는 자신의 현재 시각으로 신선도를 다시 평가하지만 worker 내부 추적·지연 통계는 달라질 수 있다. clock origin과 큐 지연을 분리해서 재현해야 한다.

### E. 얼굴 비교의 반복 계산과 입력 일관성 — 최적화 후보

`faceSimilarity`는 고정 등록 표본의 각 1024차원 절반을 매 비교마다 다시 정규화한다(camera-identity.js:38–50). 관측 특징도 각 등록 표본과의 비교 때 반복 정규화된다. 캐시할 수 있다. 단, 부동소수점 연산 순서와 점수 결과는 보존해야 한다.

별도 descriptor worker 경로와 직접 TF 경로는 같은 RGB/보정 전처리를 사용한다. 실제 모델 출력, WASM/CPU 차이, 전송 후 버퍼 보존은 기존 단위 테스트만으로 정확도를 증명할 수 없다.

### F. 등록 각도·품질 개선은 이번 범위에서 신중히 제한

`enrollmentPose`의 yaw는 정규화 x/y를 함께 사용하고 pitch는 픽셀 크기를 반영한다(camera-identity.js:82–91). 가로세로비와 roll 조합에 따른 차이는 검사할 가치가 있다. 하지만 yaw 정의 변경은 기존 각도 기준과 저장 프로필의 의미를 바꿀 수 있으므로 즉시 수정 대상에서 제외한다.

흐림 검출 추가, 좋은 표본 교체, 형상 outlier 비율 변경, 정렬/조명 보정 변경도 새 수락 기준 또는 점수 분포 변경이 될 수 있다. 이번 계획에서는 측정과 호환성 평가까지만 하고 자동 도입하지 않는다.

## 5. 실행 순서와 구체적 작업

### 1단계 — 현행 정책과 평가 기반 고정

1. 상수뿐 아니라 위 시간·점수·분기·legacy/default 경로를 fixture로 고정한다. 시작/복귀 인증, 졸음·휴대폰 동시 발생, 얼굴 부재 우선순위를 포함한다.
2. 기존 상태 입력 시퀀스를 재생하는 공통 harness를 만든다. frame ID, epoch, 촬영·처리·수신 시각, 영상 크기, 각 채널 관측 ID를 기록한다.
3. 임베딩·원본 얼굴 영상을 기본 로그에 넣지 않는다. 진단은 점수, 나이, 상태 전환 이유, 모델 처리 시간 위주로 남긴다. 실제 영상 평가 자료는 별도 동의를 받아 로컬에서 사용한다.
4. baseline과 수정본이 동일한 정상 입력 시퀀스에서 동일한 상태·전환 시간을 내는지 먼저 비교한다.

완료 조건: 정책 숫자/수식 변경 0건, 정상 경로의 결정 재생 결과 일치. 현재 기준 회귀 테스트 결과를 보존한다.

### 2단계 — 관측 중복과 손 대상 연결 수정

대상: camera-inference.js, camera.js, camera-focus.js, camera-idle.js, camera-verification.js.

1. 손끝 관측에 handedness와 원본 위치의 연결 정보를 유지한다. 직전 대응 관계를 이용해 같은 손끼리 비교하고, 새로 등장한 손은 기준점만 초기화한다. 최소 거리 대응의 동률·불확실 상황은 움직임을 만들어내지 않도록 처리한다. 움직임 임계값 .025와 시간은 그대로 둔다.
2. 얼굴과 휴대폰 관측 ID를 분리한다. 휴대폰 완료는 휴대폰 증거만 갱신하고 같은 얼굴 프레임의 평활화·이동 표본·인증 표를 다시 추가하지 않는다.
3. 관측 추가와 현재 시각에서의 상태 조회를 분리한다. 기존 만료·유예·재개 타이머와 즉시 휴대폰 일시정지는 유지한다. 새 프레임 없이 얼굴 증거를 계속 연장하는 경로만 제거한다.
4. `camera-verification`의 최근 인식 시간 통계도 같은 얼굴 관측을 새 관측으로 취급하지 않도록 이벤트 계약을 맞춘다. 시작/복귀 인증 조건은 그대로 둔다.

검증: 손 순서 반전, 한 손 소실/재등장, 교차, pose 손목+hand 중복; 동일 얼굴에 휴대폰 이벤트 0/1/여러 회; 눈 뜸/감김 전환 직전 지연; 499/500ms 얼굴 부재, 749/750ms 눈 뜸, 4499/4500ms 졸음, 1999/2000ms 복귀. 중복 이벤트 개수만 바꿔 얼굴 판정 결과가 달라지면 실패다.

### 3단계 — epoch·시각·좌표계 정합성 수정

대상: camera.js, camera-worker.js, camera-inference.js, camera-phone.js, camera-framing.js.

1. 캡처 시각, worker 수신 시각, 추론 시작/끝 시각을 별도 필드로 관리한다. performance.timeOrigin 등을 이용해 같은 시간축으로 변환하고 샘플 기반 clock 정합성 테스트를 둔다. `observedAt`은 실제 촬영 시각으로 유지한다.
2. 기존 1500ms maxAge와 지연 기반 hold 공식은 그대로 둔 채 실제 지연이 통계에 들어가도록 한다. 기존 폴백 조건·횟수는 바꾸지 않는다.
3. epoch 전환 또는 프레임 좌표계 변경 시 pose/hand/이동 기준점/확대 검색 캐시를 한 번에 무효화한다. 이전 작업 완료는 새 세션에 반영하지 않는다.
4. 손바닥 보정에는 그 영상·epoch에 대응하는 hand 결과를 연결한다. 서로 다른 시점의 손과 휴대폰 박스가 겹친 것으로 간주되지 않도록 데이터 연결을 수정한다. 기존 색상·겹침 임계값과 감점 공식은 보존한다.
5. crop→원본 좌표 복원, z 스케일, 가로·세로·비정방형 영상의 변환을 동일 fixture로 검증한다. 단순 화면 크기 변경 때문에 위치가 이동한 것으로 판정하지 않게 한다.

검증: 큐 지연 0/300/1200ms, 결과 역순·중복·세션 종료 뒤 도착, 1499/1500/1501ms 신선도 경계, 가로세로 전환, 백그라운드 복귀, worker 교체. 추론 실행 시간과 종단 지연을 구분해 보고한다.

### 4단계 — 얼굴 비교의 수치 동등 최적화

대상: camera-identity.js, face-descriptor-client.js, face-descriptor-worker.js.

1. 등록 프로필 로드 시 RGB/보정 절반의 정규화 결과를 한 번 계산해 private matcher 상태에 보관한다. 관측 특징은 프레임·후보별 한 번만 정규화한다.
2. 동일 함수와 동일 연산 순서를 유지하여 최종 점수·후보 선택·형상 점수·투표 결과가 baseline과 일치하게 한다. 프로필 갱신/삭제/종료 때 캐시도 폐기한다.
3. 두 descriptor 실행 경로에 동일한 원본/보정 입력을 공급해 텐서 크기, dtype, RGB 채널, 정규화, NaN 처리 및 해제 동작을 비교한다.
4. 얼굴 후보가 품질 검사에서 제외됐을 때 원본 faceIndex 대응을 유지하는 현행 로직을 회귀 테스트한다. 배열 순서만 달라져 다른 얼굴에 눈·시선 신호가 붙지 않는지 확인한다.
5. 프레임별 descriptor 대기를 더 비동기화하거나 모델을 바꾸는 것은 별도 구조 변경이므로 이번 단계에 포함하지 않는다.

검증: 실제 등록 프로필과 합성 경계 벡터에서 점수 일치, .8/.5 바로 위·아래의 결과 일치, 5표 중 4표 규칙 동일, 정상·실패·재시도·close 후 메모리 회수. 처리 시간 개선은 측정값으로만 보고한다.

### 5단계 — 실제 영상 비교 후 채택

테스트를 통과했다고 실제 인식률이 높아졌다고 단정하지 않는다. 같은 영상·같은 촬영 시각 시퀀스로 전후를 비교하고, 신규 등록 없이 기존 프로필에서 먼저 평가한다.

| 평가 분야 | 필수 장면 | 결과 지표 |
|---|---|---|
| 본인 확인 | 정면/측면/상하, 안경, 역광/저조도, 가까움/멀어짐, 다른 사람, 2명 동시 등장 | 본인 거부율, 타인 수락 건수·율, 인증 소요 시간 |
| 졸음 | 짧은 깜빡임, 길게 감기, 안경 반사, 책 보며 아래 보기 | 사건별 오탐·미탐, 최초 확정 시각 |
| 자리 비움 | 짧은 얼굴 가림, 0.5초 경계, 실제 이탈/복귀 | 잘못 멈춤, 놓친 이탈, 복귀 인증 누락 |
| 무활동 | 조용한 독서, 필기, 실제 정지, 두 손 순서 반전 | 잘못된 idle 해제, 잘못된 idle 확정, 학습 시간 오차 |
| 휴대폰 | 검정/밝은 케이스, 손바닥만, 책·계산기·리모컨, 부분 가림, 화면 가장자리, 작은 휴대폰 | 사건별 precision/recall, 탐지/해제 지연, unavailable 비율 |
| 실행 환경 | 데스크톱·저사양 모바일, 가로/세로, WASM/CPU, 네트워크 로딩 실패 후 복구 | 종단 지연 p50/p95, 프레임 누락·stale 비율, 메모리 |

평가 자료는 사람·기기·조명별로 분리하고 수정에 사용한 자료와 최종 확인 자료를 나눈다. 인접 프레임을 서로 독립적인 사용자 표본처럼 집계하지 않는다. 장면별 라벨을 먼저 확정하고 동일 입력을 baseline/수정본에 공급한다.

채택 조건:

- 모든 정책 회귀와 경계 테스트 통과, 정상 입력의 전환 시간 동일.
- 동일 관측 중복 및 손 순서 반전 재현에서 잘못 생성한 증거 제거.
- 평가 세트에서 새로운 타인 수락 사례 0건. 이것이 실제 타인 수락 확률 0을 뜻하지는 않음.
- 목표 장면의 오탐이 줄고 다른 장면의 미탐·인증 실패가 악화되지 않아야 함. 표본 수와 신뢰구간을 함께 보고하고 자료가 부족하면 채택 보류.
- 속도 저하 때문에 기존 시간 한계를 넘는 관측이 늘지 않아야 함. 숫자와 입력별 결과를 남긴다.

단계별로 독립 패치와 전후 결과를 남긴다. 회귀가 발생한 단계만 되돌리고 임계값을 느슨하게 만들어 통과시키지 않는다.

## 6. 이번에 수행한 검증과 한계

- 아래 9개 테스트 파일 실행: 총 189개 통과, 실패/취소/건너뜀 0개, 약 3.0초. import된 테스트가 포함되므로 189개 모두 서로 다른 시나리오라는 의미는 아니다.
- `tests/camera-focus.test.mjs`, `tests/camera-phone.test.mjs`, `tests/camera-verification.test.mjs`, `tests/camera-framing.test.mjs`, `tests/camera.test.mjs`, `tests/face-scan.test.mjs`, `tests/face-descriptor.test.mjs`, `tests/enrollment-pitch.test.mjs`, `tests/face-security.test.mjs`.
- 손끝 배열 순서 교체만으로 `createStudyMotionTracker`가 false→true가 되는 것을 별도 Node 실행으로 재현했다.
- 실제 카메라·실제 사용자 프로필을 이용한 정확도 측정과 브라우저/실모델 테스트는 이번에 수행하지 않았다. 개선율 수치를 미리 주장할 수 없다.
- Serena는 프로젝트를 인식했으나 활성 언어 서버가 없어 심벌 조회가 불가능했다. 파일 범위 검색과 직접 코드 검토로 대체했다.
- agy-delegate 보조 검토는 실행 환경 인증·권한 제한으로 시작되지 않았다. 보조 모델의 검토 결과는 없으며 위 판단은 직접 검토한 코드와 재현 결과에 근거한다.

권장 착수 순서는 정책 고정 → 손 연결/중복 관측 → 시간·epoch 정합성 → 수치 동등 얼굴 최적화 → 실제 영상 비교다. 새 모델, 새 감지 방식, 새로운 판정 기준은 이번 계획의 실행 범위에 넣지 않는다.

## 7. 구현 및 검증 결과

- 휴대폰 결과는 얼굴과 분리해 반영한다. 휴대폰은 확정 즉시 일시정지할 수 있고, 같은 얼굴 프레임으로 졸음·이탈·시선·인증 증거를 다시 누적하지 않는다.
- 손끝은 손 방향과 위치로 연결한다. 검출 순서가 바뀌거나 가려졌다가 다시 나온 손을 움직임으로 세지 않는다.
- 촬영·Worker 수신·추론 시각을 같은 기준에서 비교한다. 세션이나 해상도가 바뀌면 이전 좌표 캐시 및 진행 중이던 관측을 폐기한다. 손바닥 감점에는 휴대폰 후보와 같은 프레임에서 측정한 손을 사용한다.
- 얼굴 특징의 정규화 결과를 재사용한다. 기존 코드와 합성 프레임 200개를 비교해 활성/레거시 경로의 점수·후보·투표 결과가 동일함을 확인했다.
- 단위 테스트 399개 및 Edge 등록·저장 테스트 통과. 실제 얼굴 모델에서 별도 Worker와 직접 실행의 특징 값도 일치했다(최대 차이 0).
- 기존 감지 모델, 임계값, 판정 시간 및 저장 형식을 유지했다. 실제 사용자의 라벨이 있는 영상으로 오탐·미탐을 전후 비교하는 단계는 남아 있다.
